深渊岛可编辑工程

当前版本0.2.0，2026年11月11日更新。
本轮加入农耕、六项技艺、鳄鱼、家居存储、航行地图、东海沉船委托、沙滩车、枪弓、饥饿烹饪、五格工具栏、选中交互和尸体剥皮流程。
操作与本轮修复详见 游戏\运行说明.txt；图文过程见 需求\开发过程文档 下的两个Word文档。

一键打开与运行
解压完整工程后，双击根目录“打开Godot编辑器.cmd”。编辑器已放在工具目录，无需另装 Godot。
双击“运行游戏.cmd”可以运行当前源工程，修改后再运行即可看到新结果。
主工程为 游戏\project.godot，主场景为 游戏\scenes\coastal_beauty.scn。
工程包默认关闭可选 Godot AI MCP 插件，普通编辑和游戏不需要 Python、uv 或 MCP。
首次打开会重建 .godot 导入缓存，时间取决于电脑与磁盘，请等待资源导入完成。

修改与再次导出
双击“一键导出Windows.cmd”，将生成独立程序到 发布\Windows。
脚本使用附带的 Godot 4.7.2 和 Windows 64 位模板，在临时副本导出，不改写正在编辑的主场景。
发布给试玩者时发送整个 Windows 文件夹，EXE 与同名 PCK 必须一起保留。
独立版不需要编辑器、Blender、Python、MCP或网络。
Windows 版使用 Forward+，需要支持 Vulkan 的显卡与相应驱动。

哪些文件改哪里
游戏\scripts       玩法控制与行为代码，按 player、fishing、boating 等模块分工。
游戏\shaders       水、草地、天气、道路与特效着色器。
游戏\assets        运行时模型、材质、数据和贴图副本。
素材\06_游戏场景资产   可编辑 BLEND、GLB、绑定结果和制作资料。
素材\07_动作源文件    Mixamo动作原件。
需求               游戏规格和两份开发过程文档。
资料               参考视频和制作流程截图。
归档               全部保留的历史版本、停用模型、原始下载包及过程材料。
整理记录            文件清单、整理记录和开发文档编制材料。
模型源工程用 Blender 编辑，修改后导出 GLB 到对应运行资产位置，再在 Godot 检查。

多人如何协作
当前工程使用 Git 和 Git LFS 管理，远程仓库为 https://github.com/shijinxiang/shenyuan-island。
仓库已公开，可通过 Git 克隆并执行 git lfs pull 获取资源。协作者取得写入权限后可以推送分支。
首次克隆的电脑需要自行准备 Godot 4.7.2，根目录 README.md 写明了引擎和导出模板的位置。
main 保存已合并版本，日常修改从 main 建立自己的功能分支，通过 Pull Request 交接和合并。
Issues 记录负责人、复现步骤、预期效果和验收结果，项目看板跟踪待处理、进行中、待验收和已完成。
主场景 coastal_beauty.scn 和 BLEND 是二进制文件，同一份文件同一时段交由一人修改。
不要多人直接共用同一个 .godot 缓存目录。同步源文件时排除 .godot、_build 和发布文件。
根目录 .gitignore 维护排除规则，.gitattributes 将模型、二进制场景、图像和 Word 等文件交由 LFS 保存。
工具中的本机编辑器和历史归档继续保存在本地完整交付包。
提交、模型交接、检查和发布的具体步骤见 CONTRIBUTING.md，版本变化见 CHANGELOG.md。

存档
交付包不包含本机个人试玩存档，新用户从新游戏开始。
交付版与交付工程使用 %APPDATA%\ShenyuanIsland 保存进度。
当前原开发目录的历史存档继续保留，打包不会删除它。

可选MCP
addons\godot_ai 与工具\GodotMCP 已随工程保留，需要AI操作时自行启用并配置服务。
普通运行不启用它，也不需要连接原开发电脑。
历史MCP说明中的绝对路径属于原电脑记录，使用前按接收者电脑调整。
